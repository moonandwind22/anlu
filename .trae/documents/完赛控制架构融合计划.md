# 完赛工程控制架构融合计划（第2课 3.2 → 本工程）

> 依据第2课 3.2"完赛工程的控制架构"（3 层 6 模块），把上传的 5 个模块融合进当前 HDMI 图片轮播工程，并严格落实第 1、2 课的思路与注意事项（最小改动、不破坏原有功能、只改应用层、参数化、渐进式每步可上板）。

## 一、已确认决策（用户拍板）

| 决策点 | 结论 |
|---|---|
| 帧缓存架构 | **维持 2 缓冲按需加载**（不改造为 4 缓冲开机预载；frame_read_write 原生支持 4 缓冲，留作后续升级路径） |
| KEY3 长按（3.2"亮度调节"） | **仅 0-255 调节值寄存器 + VOL 页显示**，不动实际视频/音频输出路径 |
| 组合键"保存设置到 Flash" | **设置锁存到寄存器组 + 数码管确认显示**；真 Flash 持久化留作后续迭代 |

## 二、现状与关键事实（勘探结论，全部已验证）

1. **工程基线 = 官方例程**：[sd_card_bmp.v](file:///workspace/src/user_source/hdl_source/SD/sd_card_bmp.v) 为 all-in-one 控制核（消抖/扫描/加载/双缓冲/1s 轮播/状态码）；顶层 [top_tf_hdmi_audio.v](file:///workspace/src/user_source/hdl_source/top_tf_hdmi_audio.v)（模块名 `top`）用 `seg_scan`+`seg_decoder` 把 `state_code` 显示在数码管上。
2. **时钟域**（第1课 3.2 表）：`sd_card_clk` 100MHz=控制域（`CLK_FREQ_HZ=100_000_000`）、`ext_mem_clk` 100MHz、`video_clk` 25MHz、`audio_mclk` 12.288MHz。**所有新增逻辑全部落在 sd_card_clk 域，不引入任何新 CDC；不碰 PLL。**
3. **板卡数码管是 6 位**（[pin.adc](file:///workspace/src/user_source/constraints_source/pin.adc) 只有 `seg_sel[5:0]`；8 根段选线 `seg_data[7:0]` 含小数点）。上传的 `seg7_panel` 是 8 位设计 → **必须做 6 位适配**（VOL/PRD 页表头从 digit7-5 移到 digit5-3、扫描回绕 6 位）。
4. **段选约定完全一致**（可无缝替换 seg_scan/seg_decoder）：低有效，`{dp,g,f,e,d,c,b,a}`，bit0=A 段；位选低有效 one-hot；按键低有效（按下=0），与 router 的 `key2_n/key3_n` 约定一致。
5. **按键映射**（3.2 定义 ↔ 板卡）：板上 `key1`(下一张)→router `key2_n`；板上 `key2`(轮播/长按)→router `key3_n`。
6. **提交路径保持不动**：`read_req` 每帧仅在 VS 沿发起一次、`read_addr_index` 每帧在 S_ACK 锁存一次（[video_timing_data.v](file:///workspace/src/user_source/hdl_source/SD/video_timing_data.v#L64-L72)、[frame_fifo_read.v](file:///workspace/src/user_source/hdl_source/SD/frame_fifo_read.v#L136-L144)），现有 `disp_buf_idx`（0↔1 单 bit 翻转）路径已被验证帧原子，**2 缓冲下无需新增提交桥**。
7. **router 默认参数恰为 100MHz 定制**：DEBOUNCE_CYCLES=1e6(10ms)、HOLD_CYCLES=1e8(组合键 1s)、KEY3_LONG_CYCLES=5e7(0.5s)，与 3.2 定义一致；实例化时仍按 `CLK_FREQ_HZ` 参数化导出（消抖取 20ms 对齐官方）。
8. **TD 工程 .al 是纯 XML**，直接追加源文件条目即可（格式照抄现有无 AutoExcluded 条目）。
9. 沙箱无 iverilog/verilator → 验证以"分阶段上板"为主；实现时可选尝试 `apt-get install iverilog` 做行为级 TB（失败则跳过）。

## 三、3.2 架构 → 本工程落地映射

3.2 的 6 模块中，`media_player_control`（播放控制）未上传 → 其职责由**演进后的 sd_card_bmp** 承担（装载请求/提交/轮播计时本就在此，保持现有已验证流程，仅替换"下一张目标"来源）；`osd_overlay_24` 未上传 → 不在本次范围。

### 事件 → 功能对照表（3.2 定义 → 落地实现）

| 3.2 定义 | 事件来源 | 落地行为 | 实现位置 |
|---|---|---|---|
| KEY2 单击 = 下一张 | `key2_event` | 推进序列：脉冲 `media_policy.next_event` → `media_id+1` → 资源校验 → 发起新装载 | sd_card_bmp 新增推进状态机 |
| KEY3 单击 = 自动轮播开关 | `key3_event` | 保持现有 toggle 逻辑（`scan_done && found>1`） | sd_card_bmp（改事件源） |
| KEY3 长按 0.5s = 调节 | `key3_long_event` | `volume` 寄存器步进 +32（0→32→…→224→0 回绕，默认 128），脉冲 `vol_event` | sd_card_bmp |
| KEY2+KEY3 长按 1s = 保存 | `save_event` | 锁存 `saved_volume/saved_period_sec/saved_auto_en`，脉冲 `prd_event`（PRD 页 2s 作保存确认） | sd_card_bmp |
| 策略层决定"下一张切哪张" | `media_policy.media_id` | 模 4 推进，唯一决策者；`next_index_limited` 函数删除 | media_policy 原样 + sd_card_bmp 消费 |
| 资源校验（image_complete[target]） | 发现位图 `img_found_bits = 4'b1111 >> (4-img_found_count)` | 推进后目标无效则重试脉冲（≤3 次，4 次回绕回到原点）→ 全无效报 `ERR_NO_RESOURCE=0x53` 不切换；少图卡（1/2/3 张）经重试推进自动回绕，语义等价原 `next_index_limited` | sd_card_bmp |
| 请求忙（上一个未完成） | `load_busy` | 沿用官方"挂起 1 次"机制（`next_req_pending`，目标=media_id，脉冲期间被封锁故目标稳定）；已挂起时再按 KEY2 → `ERR_REQUEST_BUSY=0x52`，不累积 | sd_card_bmp |
| 轮播周期运行时可配置 | 新端口 `period_cfg_valid/period_cfg_cycles` | 范围检查 0.5s~30s（越界 `ERR_PERIOD_RANGE=0x51` 保持旧值）；默认 **2.5s**（3.2：不是官方的 1s）；生效后更新 `period_sec` 并脉冲 `prd_event`；顶层暂 tie 0（无 UART/菜单源，端口预留） | sd_card_bmp |
| 数码管三页面轮播 | `seg7_panel` | PIC/VOL/PRD 页 1s 轮播；提交切图脉冲 `pic_event` 强制 PIC 页 2s；VOL 显示 volume（double-dabble BCD）；PRD 显示周期整秒（`period_sec`，四舍五入——2.5s 显示为 3，小数点显示留作后续） | seg7_panel(6 位适配版) + sd_card_bmp |
| 错误码体系 | `error_code[7:0]` 寄存器 | `ERR_NONE=0x00/0x51/0x52/0x53`，新增输出端口，顶层暂不接（UART/OSD 后续） | sd_card_bmp |
| fast_boot_gate（首图开门） | `image_complete=发现位图`、`ingest_done=scan_done`、`player_enable_raw=scan_done` | `player_enable_fast = scan_done && img_found_bits[0]` 门控推进路径 —— 与现有 `scan_done && found>0` 条件**语义等价**，纯架构化接法；2 缓冲下语义降级（用户已知悉，4 缓冲升级时自动恢复完整语义） | fast_boot_gate 原样 + sd_card_bmp |
| 上一张（第 2 课 2.1 练习） | 无 | 3.2 完赛事件体系无 prev 事件（被组合键体系取代），本融合遵循 3.2 最终定义；其"长按防重复/防误触"思路由 router 内建 `key3_long_marked` 原生保证 | — |
| 图片-音频联动 | `audio_id/linked_event` | 预留不接（本工程为固定 1kHz 测试音），后续课程可接 | media_policy 原样 |

### 阶段 2：控制策略层（media_policy 接管"下一张"）

**新增文件**：`SD/media_policy.v`、`SD/fast_boot_gate.v`（原样）。

**修改 sd_card_bmp.v**：
1. 实例化 `media_policy`：`clk/rst_n` 同域；`next_event`←推进脉冲 `adv_next_pulse`；`menu_up/menu_down/menu_select`→1'b0；`image_complete`←`img_found_bits`（组合导出 `4'b1111 >> (4 - img_found_count[2:0])`，0 张时为 0，policy 门 `image_complete != 0` 自动拒绝推进）；`media_id` 输出消费；`audio_id/linked_event/menu_state` 悬空。
2. 实例化 `fast_boot_gate`：`ingest_done`←`scan_done`、`image_complete`←`img_found_bits`、`player_enable_raw`←`scan_done`；`player_enable_fast`→门控推进路径；`first_image_ready` 悬空（状态预留）。
3. **新增推进状态机**（替代"按键直接置 next_req_pending"）：
   - 触发源：`key2_event`（`player_enable_fast=0` 时静默忽略；`adv_active|next_req_pending` 时报 0x52 不发脉冲）或自动轮播到期（沿用现有 auto 条件结构：`scan_done && auto_play_en && display_valid && !load_busy && first_image_committed && next_req_pending==0 && img_found_count>1`，auto_cnt 上限改为 `period_cycles`）。
   - `adv_state`：PULSE（发 1 拍 `adv_next_pulse`）→ CHECK：若 `img_found_bits[media_id]` → 目标有效：`!load_busy` 直接走现有"手动下一张"装载分支（`load_idx=media_id`、`load_sector=sector_lut(media_id)`、`pending_buf_idx/write_buf_idx=next_buf_lut(disp_buf_idx, display_valid)`），若 `load_busy` 则置 `next_req_pending`；若目标无效且 `adv_retry<3` → 重试脉冲，否则报 0x53（4 次推进回绕后 media_id 回到原显示值，无失步）。清 `adv_active`。
   - 挂起服务：现有 pending 分支的目标来源改为 `media_id`（脉冲被封锁故挂起期间 media_id 稳定）。
4. **周期可配置**：新 parameter `PERIOD_CYCLES=250_000_000`（2.5s）、`MIN_PERIOD_CYCLES=50_000_000`（0.5s）、`MAX_PERIOD_CYCLES=3_000_000_000`（30s，<2^32 ✓）；新输入端口 `period_cfg_valid/period_cfg_cycles`；生效时更新 `period_cycles` 内部寄存器、`period_sec <= 四舍五入(period_cycles/CLK_FREQ_HZ)`，越界报 0x51 保持旧值。
5. **错误码**：`error_code[7:0]` 寄存器 + 新输出端口（0x00 复位默认，错误锁存最近一次）。
6. 删除 `next_index_limited` 函数（策略层接管）；保留 `sector_lut/next_buf_lut`、装载/提交/write_finish 三级同步流程**原样**。首图装载分支原样（policy 复位值 0 与首图一致，无失步）。

**修改 [top_tf_hdmi_audio.v](file:///workspace/src/user_source/hdl_source/top_tf_hdmi_audio.v)**：sd_card_bmp 实例新增 `.period_cfg_valid(1'b0), .period_cfg_cycles(32'd0), .error_code()` 连接。

**修改 .al**：追加 2 条目（46/47）。

**上板验证**：默认轮播 ~2.5s（秒表）；KEY2 编号推进 1→2→3→4→1；TF 卡放 1 张图按 KEY2 不切换（0x53）；放 2 张图 0↔1 回绕；阶段 1 全部用例回归。

## 八、假设与风险

1. **假设**：板上 `seg_sel[0]` 对应最右数码管位；若相反，阶段 3 预案一行修正（dig_n 位序翻转），不影响其他逻辑。
2. **假设**：直接编辑 .al XML 与 TD GUI 添加源文件等价（格式已比对现有条目）。
3. **风险**：seg7_panel 页面布局适配笔误 → 阶段 3 上板逐页目检（三页面 + 强制保持 + BCD 值）。
4. **风险**：推进状态机与装载分支互锁遗漏（load_busy/display_valid 条件）→ 装载三分支的门槛条件保持原结构，仅替换目标来源；阶段 2 用例 8/9/10 专项覆盖。
5. **已知限制**：fast_boot_gate 在 2 缓冲下语义降级为首图开门（用户已确认接受）；PRD 页显示整秒（2.5s 显示为 3）；saved_* 寄存器断电即失（无 Flash）——三项均为有意决策，非缺陷。
6. **回退**：每阶段一个 git 提交；任一阶段上板失败可整体 revert，不影响后续重试。
